# 컴피티션 자동 리서치 봇

국내외 공모전·경진대회를 여러 소스에서 자동 수집하고, 리서치 기준 3가지를 자동 판정한 뒤, "확정 컴피티션 공지 목록"과 동일한 컬럼의 엑셀 후보 목록으로 저장합니다. GitHub Actions로 매주 사람 개입 없이 자동 실행됩니다.

> **이 프로젝트를 처음 보신다면 [`입문.md`](입문.md)부터 읽으세요.** 크롤링이 뭔지,
> 이 봇이 왜 이렇게 만들어졌는지, 결과 엑셀을 어떻게 읽는지를 프로그래밍 지식 없이도
> 따라올 수 있게 설명해 둔 문서입니다. 이 README는 실제로 쓸 사람을 위한 요약이고,
> 코드를 고칠 사람은 `DEVELOPMENT.md`를 보시면 됩니다.

## 자동 판정 기준 (컴피티션 스크래핑 문서 기준)

1. 재학생 참가 가능 — 응모대상·본문에서 판정 (청소년 전용, 임직원 전용 등 자동 탈락)
2. 팀(2인 이상) 참가 가능 — "2~4인", "팀 구성" 등 패턴 탐지, "개인 참가만"은 탈락
3. 신청 마감까지 2주 이상 — 접수기간 파싱 후 D-14 미만 자동 탈락

판단이 애매한 대회는 버리지 않고 `공지 상태 = 신규후보(확인필요)`로 남깁니다.
로컬 LLM이 부적합으로 본 건도 지우지 않고 `신규후보(LLM의심)`으로 표시만 합니다 —
3B 모델은 근거가 없을 때도 단정하는 일이 있어서 삭제 권한을 주지 않았습니다.

## 출력

`data/후보_컴피티션_목록.xlsx` — 기존 확정 목록과 동일한 15개 컬럼(공지월, 학부, 대회명, 주최/주관, 분야/주제, 신청 마감일, 대회 일정, 팀 인원, 참가 자격, 공식 링크, 상금/혜택, 참가비, 공지 상태, 담당자, 비고). 실행할 때마다 새 대회만 추가되고 기존 행은 유지됩니다(공식 링크·대회명 기준 중복 제거). 비고 컬럼에 자동 판정 근거가 기록됩니다.

## 완전 자동화 설정 (GitHub Actions — 서버 불필요, 무료)

1. GitHub에 새 레포지토리를 만들고 이 폴더 전체를 업로드(push)합니다.
2. 끝입니다. `.github/workflows/scrape.yml`이 매주 월요일 오전 9시(KST)에 자동 실행되어 엑셀을 갱신하고 커밋합니다.
3. 수동으로 즉시 돌려보려면: 레포의 Actions 탭 → "컴피티션 자동 리서치" → Run workflow.

### (선택) Ollama 로컬 LLM 정밀 추출

규칙 기반만으로는 "팀 인원", "대회 일정", "참가비", "한 줄 소개" 같은 서술형 필드를 정확히 못 채우는 경우가 많습니다. Ollama(로컬 LLM 실행 도구)가 떠 있으면 로컬 모델이 각 공고 본문을 읽고 해당 필드들과 학부 분류, 참가 자격 판정까지 채워 넣습니다. API 키와 비용이 전혀 들지 않으며, 서버가 없으면 자동으로 규칙 기반만 사용합니다.

GitHub Actions에서는 워크플로가 러너 안에 Ollama를 자동 설치·실행하므로 별도 설정이 필요 없습니다. 다만 무료 러너는 GPU가 없어 LLM 단계가 느립니다(3B 모델 기준 대회 1건당 대략 30초~1분). 그래서 `LLM_MAX_ITEMS`(기본 40)로 LLM 처리 건수를 제한하며, 초과분은 규칙 기반으로 채워집니다. 참고로 퍼블릭 레포는 Actions 사용시간이 무제한이지만, 프라이빗 레포는 무료 한도가 월 2,000분이라 매주 30~60분씩 쓰면 한도의 상당 부분을 차지할 수 있습니다.

로컬 실행 시:

```bash
# 1) https://ollama.com 에서 Ollama 설치 후
ollama pull qwen2.5:3b        # 또는 한국어 강화 모델: ollama pull exaone3.5:2.4b
# 2) 그대로 실행 (Ollama 앱이 켜져 있으면 자동 감지)
python main.py
# 다른 모델/호스트를 쓰려면
OLLAMA_MODEL=exaone3.5:2.4b OLLAMA_HOST=http://localhost:11434 python main.py
```

기본 모델은 `qwen2.5:3b`(약 1.9GB, 한국어 무난)이고, 한국어 공고 이해도가 더 중요하면 LG의 `exaone3.5:2.4b`를 권장합니다. 워크플로의 `OLLAMA_MODEL` 값만 바꾸면 됩니다.

## 로컬 실행

```bash
pip install -r requirements.txt
python main.py                          # 기본: 목록 3페이지, 상세 60건
PAGES=5 MAX_DETAILS=100 python main.py  # 더 넓게 수집
# Ollama가 켜져 있으면 정밀 추출 자동 활성화 (위 Ollama 섹션 참고)
```

로컬에서 주기 실행하려면 (macOS/Linux) `crontab -e`에 아래 한 줄을 넣습니다.
`run.sh`가 Ollama 기동까지 알아서 하고, `flock`이 중복 실행을 막고, 결과는 `cron.log`에 쌓입니다.

```
0 8 * * 1 /usr/bin/flock -n /tmp/competition-scraper.lock "/home/schoaq/competition-autoscraper 2/run.sh" >> "/home/schoaq/competition-autoscraper 2/cron.log" 2>&1
```

eez192 서버에는 위 설정이 이미 등록되어 매주 월요일에 자동 실행됩니다.
**서버 시간대가 HKT(UTC+8)라 08:00으로 잡혀 있고, 이것이 한국시간 09:00입니다.**
자세한 내용은 `DEVELOPMENT.md` §7 참고.

Windows는 작업 스케줄러에 `python main.py`를 주간 작업으로 등록하면 됩니다.

### 서버 관리

```bash
./serve_web.sh          # 안 떠 있으면 띄운다 (떠 있으면 아무것도 안 함)
./serve_web.sh stop     # 내리기
tail -f data/web.log    # 접속·오류 로그
```

`crontab`에 2분마다 위 헬스체크가 걸려 있어서 **서버가 죽거나 머신이 재부팅돼도 알아서
다시 뜹니다**(`serve_day1.sh`와 같은 방식). 실측으로 프로세스를 죽여보니 5초 만에 복구됐습니다.
gunicorn(워커 1 + 스레드 8)으로 돌고, `setsid`로 로그인 세션과 분리돼 있어 터미널을 닫아도
계속 살아 있습니다.

`./run_web.sh`는 개발용 단독 실행입니다(127.0.0.1 고정, Flask 개발 서버).

### 알아둘 것

- 비밀번호는 `serve_web.sh`의 `WEB_PASSWORD` 기본값입니다. 바꾸려면
  `WEB_PASSWORD='새비번' ./serve_web.sh`로 다시 띄우고, crontab 줄에도 같이 넣어야 합니다.
- **0.0.0.0에 열려 있습니다.** 같은 망이면 누구나 로그인 화면까지는 닿습니다.
  틀린 비밀번호에는 1초 지연을 둬서 대입 시도를 늦췄지만, 학교 밖에서도 닿는 주소라면
  비밀번호를 더 길게 바꾸시길 권합니다. 아예 닫으려면 `WEB_HOST=127.0.0.1`로 바꾸고
  각자 SSH 터널(`ssh -L 8000:localhost:8000 schoaq@eez192`)로 쓰면 됩니다.

**기각 사유가 규칙을 가르칩니다.** `재학생이 참가할 수 없음`·`팀 참가가 안 됨`으로 기각하면
그 공고가 부정 사례로 쌓입니다. 여태 `evolve.py`는 사람이 "확정"한 긍정 사례만 받을 수
있었고, 그게 §9-1 규칙 오염의 근본 원인이었습니다. 목록 하단의
`검수 결과를 평가셋으로 내보내기`가 `data/평가셋_검수.jsonl`을 만듭니다.

데이터는 `data/review.sqlite3`에 쌓이고, 엑셀은 이제 **사람이 고치는 대상이 아니라
DB에서 뽑아내는 산출물**입니다.

scraper/output.py        # 확정 목록과 동일 컬럼의 엑셀 생성·누적
evolve.py                # AlphaEvolve 규칙 진화 루프

.github/workflows/evolve.yml  # 매월 규칙 진화 자동 실행

창업·기업지원 쪽을 같이 보고 싶을 때만 켜세요: `SOURCES=wevity,kstartup python main.py`

환경변수로 소스를 켜고 끕니다: `SOURCES=wevity,devpost python main.py`
한 소스가 실패해도 나머지 소스는 계속 수집됩니다.

> **소스가 늘면 실행 시간도 늘어납니다.** 사이트에 부담을 주지 않으려고 요청 사이에
> 1초씩 쉽니다. 이 서버 실측(2026-07-26, 기본값 `PAGES=3 MAX_DETAILS=60`, LLM 제외):
> **13개 소스 · 455건 수집 · 약 19분.** 급하면 `MAX_DETAILS`를 줄이거나
> `SOURCES`로 필요한 소스만 켜세요 (`MAX_DETAILS=8`이면 96건 · 약 7분).

> **같은 대회가 여러 사이트에 동시에 올라옵니다.** 국내 소스 5곳은 서로 겹치는 공고가
> 많습니다. 중복 제거는 공식 링크와 **정규화한 대회명**(공백·괄호·문장부호 제거)으로 하므로
> `대학가요제`/`대학 가요제`, `『…』`/`…` 같은 표기 차이는 한 줄로 합쳐집니다.
> 다만 `…학술대회`/`…학술대회 공모전`처럼 단어가 더 붙은 건은 일부러 안 잡습니다
> (유사도까지 가면 다른 대회를 합쳐버립니다). 실측 18쌍 중 5쌍이 잡히고 13쌍은 남으니,
> 남는 건 비고란의 소스 표기를 보고 사람이 합치면 됩니다.

해외(Devpost) 항목은 API가 참가 자격 전문을 제공하지 않아 재학생·팀 여부가 "확인필요"로 남는 경우가 많습니다. Ollama 정밀 추출을 켜면 정확도가 올라가고, 최종 확인은 비고란의 공식 링크에서 하면 됩니다. 해외 대회는 시차·온라인 여부(비고의 "장소" 참고)도 함께 확인하세요.

## AlphaEvolve 규칙 자동 진화

DeepMind AlphaEvolve의 핵심 원리(후보 생성 → 자동 평가 → 상위 선택 → 변이 → 반복)를 축소 적용해, 판정 규칙이 검수 결과를 먹고 스스로 개선되도록 했습니다.

동작 방식: ① 엑셀에서 사람이 '확정'으로 검수한 대회가 `data/평가셋.jsonl`에 정답 사례로 자동 축적됩니다(시드 12건 포함). ② `evolve.py`가 현재 규칙을 시조로 개체군을 만들고, 각 후보를 평가셋 정확도로 채점합니다. ③ 상위 후보만 살아남고, Ollama가 오답 사례를 보고 정규식·키워드 수정을 제안하거나(LLM 변이) 오답 텍스트에서 토큰을 채굴해 추가합니다(휴리스틱 변이 — Ollama 없이도 동작). ④ 세대를 거듭해 최고 점수 규칙이 `data/rules.json`으로 저장되고, 다음 스크래핑부터 `main.py`가 자동 적용합니다. `data/evolve_log.json`에서 세대별 점수 추이를 볼 수 있습니다.

안전 설계: 진화 대상은 임의 코드가 아니라 **검증 가능한 설정(정규식·키워드 JSON)으로 제한**됩니다. 모든 후보는 개체군 진입 전에 구조 검증, 정규식 컴파일 검증, 길이·개수 상한 검사를 통과해야 하며, 실패한 후보는 폐기됩니다.

실행: `python evolve.py` (환경변수 `GENERATIONS`, `POPULATION` 조절 가능). `evolve.yml` 워크플로가 매월 1일 자동으로 검수 결과 수확 → 진화 → 커밋까지 수행합니다. 평가셋이 쌓일수록 진화 품질이 올라가므로, 부적합 사례(탈락시켜야 할 공고)도 `평가셋.jsonl`에 `"student_ok": false` 형태로 몇 건 추가해 두면 오탐 방지에 큰 도움이 됩니다.

## 사이트 추가 로드맵

새 소스는 `scraper/`에 파일 하나 만들고 `main.py`의 `SOURCE_REGISTRY`에 한 줄 등록하면 됩니다. 반환 형식은 `wevity.py`/`devpost.py`와 동일한 dict 리스트입니다.

씽굿·링커리어·캠퍼스픽·MLH·Unstop은 "JS 렌더링이라 불가"로 적혀 있었지만, 실제로는
목록을 내부 JSON/GraphQL로 가져오고 있어서 **헤드리스 브라우저 없이 추가했습니다**
(위 표 참고). 남은 후보는 아래입니다.

- Kaggle — 공식 API 있으나 API 키 필요
- HackerEarth — 브라우저 UA로도 403(봇 차단). 우회는 시도하지 않음
- 온오프믹스·대티즌 — 실측 결과 공모전 비중이 낮거나 목록 구조가 불안정

## 유의사항

- 요청 사이 1초 지연을 두어 사이트에 부담을 주지 않도록 했습니다. 위비티 이용약관을 확인하고, 수집 데이터는 내부 공지용으로만 사용하세요.
- 사이트가 리뉴얼되면 파싱이 깨질 수 있습니다. 셀렉터 대신 URL 패턴·라벨 텍스트 기반으로 짜서 웬만한 변경에는 버티지만, Actions 로그에서 수집 건수가 0이 되면 `wevity.py`를 점검하세요.
- 자동 판정은 보조 수단입니다. 공지 확정 전 `확인필요` 표시 건과 공식 링크는 한 번 확인하는 것을 권합니다.
